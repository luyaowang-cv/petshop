# 小程序 MVP 任务拆解（Tasks）

> 前置：[miniprogram-mvp-spec.md](./miniprogram-mvp-spec.md)、[miniprogram-mvp-plan.md](./miniprogram-mvp-plan.md)
> 开发方式：TDD

---

## TDD 约定

1. 每个后端任务：**先写 `.spec.ts` 测试（依据 spec §10 验收标准）→ 跑测试确认红 → 实现 → 跑测试确认绿**。
2. 测试文件沿用现有 Jest 约定：与源码同目录、`*.spec.ts`（`server/package.json` 已配 `rootDir: src`）。
3. 微信、存储等外部依赖一律**抽象为接口 + mock**，单测不联网。
4. 完成一个任务、测试全绿后再进入下一个；禁止先写一堆实现再补测试。
5. 前端（小程序/工作台）不强制单测，但关键逻辑（状态机、表单校验）抽纯函数尽量可测。

## 任务列表

### Phase 1：后端基础设施

| ID | 任务 | 说明 | 先写的测试 |
|----|------|------|-----------|
| T-01 | 数据库 schema 变更 + 迁移 | 枚举加 `CONFIRMED`/`REJECTED`；`Customer.openid/avatarUrl`、`Pet.imageUrl`、`PetshopService.imageUrl`、`Appointment.rejectReason/customerNote` | 迁移可生成（无单测）；用 `prisma migrate` 生成并验证字段 |
| T-02 | 微信 API 客户端 | 封装 `code2session`、`getuserphonenumber`，定义为接口，注入实现 | mock 微信 HTTP，测试换取 openid/手机号的解析、失败场景 |
| T-03 | Customer JWT 策略/守卫 | 新增独立顾客 JWT（区分 admin），签发/校验 `customerId` | 顾客 token 校验通过；admin token 不能过顾客守卫；反之亦然 |
| T-04 | 图片上传服务 | 上传接口 + 类型/大小校验（≤5MB，jpg/png/webp），返回 URL | 合法图片返回 URL；超大小/非法格式被拒 |

```

  → T-14 → T-15 → T-16 → T-17 → T-18 → T-19 → T-20 → T-21 → T-22   # 小程序
```
